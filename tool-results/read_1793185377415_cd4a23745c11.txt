    10→## Build Philosophy
    11→
    12→1. **De-risk first.** The riskiest unknowns (Qloo key + parameter names, free LLM tool-calling, free image generation) are tested in Phase 2 before any UI exists.
    13→2. **Vertical slices.** Each phase ends with something runnable and verifiable.
    14→3. **Fallbacks are features.** Scripted agent, template descriptions and SVG sketches are built, not "if time permits".
    15→4. **Feature freeze Friday noon.** After that: bug fixes, README, submit.
    16→5. **Cut order if late:** compare panel polish → drop timeline polish → line-sheet polish → replace flow. **Never cut:** agent thinking panel, scored collection with evidence, describe→approve→image flow, side-by-side compare (basic version), README/license/live URL.

    89→Loads `.env.local` (use `process.loadEnvFile?.('.env.local')` on Node 20.12+ or `dotenv`-free manual parse). Calls, in order, printing status code, first 2 results, and the exact URL (key omitted):
    90→1. `GET /search?query=Arctic Monkeys&types=urn:entity:artist&take=3` (famous artist)
    91→2. `GET /search?query=<a small indie band you know>&types=urn:entity:artist&take=3` (record whether it's found)
    92→3. `GET /v2/tags?filter.query=retro gaming&take=5`
    93→4. `GET /v2/insights?filter.type=urn:tag&signal.interests.entities=<id from 1>&take=10`
    94→5. `GET /v2/insights?filter.type=urn:entity:brand&signal.interests.entities=<id from 1>&take=10`
    95→6. `GET /v2/insights?filter.type=urn:entity:videogame&signal.interests.tags=<tag id from 3>&take=10`
    96→7. `GET /v2/insights?filter.type=urn:entity:place&signal.interests.entities=<id from 1>&filter.location.query=Columbus, Ohio&take=10`
    97→8. Same as 5 with `&filter.exclude.entities=<first result id>` (confirms exclusion works)

   348→## Common Failure Points and Debugging
   349→
   350→| Symptom | Likely cause | Fix |
   351→|---|---|---|
   352→| Qloo `401`/`403` | Wrong header or key for wrong host | Header must be `X-Api-Key`; base must be `hackathon.api.qloo.com` |
   353→| Qloo `400` on videogame | Used `urn:entity:video_game` | Use `urn:entity:videogame` |
   354→| Agent never finishes | Model keeps calling tools | Enforce max 8 calls in loop; return "tool budget exhausted — call finish" |
   355→| LLM returns invalid JSON | Free model drifting | `json: true`, strict Zod, one retry, template fallback |
   356→| Groq/Gemini `429` | Free tier rate limit | Chain falls through; check `/api/status` and dashboards |
   357→| SSE shows nothing until the end | Response buffered | Verify headers in `05-BACKEND-SCHEMA.md`; send a leading comment `: ok\n\n`; flush per event |
   358→| `FUNCTION_INVOCATION_TIMEOUT` | Run exceeded the Vercel limit | `maxDuration = 60`; cut agent calls; lower timeouts |
   359→| Cloudflare `401`/`403` | Token lacks Workers AI permission or wrong account id | Recreate token; re-copy Account ID |
   360→| Image comes back but won't display | Missing `data:image/jpeg;base64,` prefix | Prefix in `cloudflare.ts` |
   361→| Images vanish on reload | By design (memory only) | Card shows "Generate again"; Download first |
   362→| `sessionStorage` quota error | Storing images | Strip `dataUrl` in `storage.ts` |
   363→| Hydration mismatch | Reading storage during render | Read in `useEffect` |
   364→| Brand names appear in image prompt | Moderation not applied | Ensure `brandNames` sent by client and stripped server-side; unit test |
   365→| Collection has <5 items | Budget too tight/eligible set small | Relax per-item cap once (rules step 6) and add note |
   366→| Fonts not loading | Missing `variable` class on `<body>` | Apply all three font variables |

   370→## Appendix A — Devpost Description (paste and edit)
   371→
   372→**Problem.** Independent artists and creators often default to a logo on a black tee because they don't know what their specific fans would actually want to own — and a bad first print run ties up scarce cash.
   373→
   374→**Solution.** MerchDesk is an agent that turns a creator's audience into a launch-ready merch collection. You describe your fans (or search an artist), and the agent researches their cultural taste with Qloo, then proposes 5–8 makeable products with estimated prices, margins, break-even quantities, supplier briefs, local collab partners and a Core/Hero/Limited drop plan. Every product is first described in words; only after you approve (or tweak) the description does MerchDesk generate a concept image.
   375→
   376→**How it uses Qloo.** An LLM agent calls Qloo tools — entity search, tag search, taste (tag) analysis, and related-entity insights for brands, games, shows, books and local places with a city filter. If the artist isn't in Qloo, the agent notices and switches to genre and interest tags on its own. When a user rejects a product, the agent re-queries Qloo with that product's driving entities excluded and swaps in a replacement. A deterministic scoring layer matches Qloo's audience affinity to a catalog of real, makeable products, and every pick carries an evidence trail ("← retro gaming", "← audience affinity: …").
   377→
   378→**Why it beats a generic LLM.** A side-by-side panel shows the same input answered by a generic LLM (no Qloo) and by MerchDesk. The LLM never invents data: tool results come from Qloo, numbers come from code, and the LLM only names products and writes descriptions from supplied facts.
   379→
   380→**Honesty.** Qloo supplies affinity, not purchase data — copy says so. Prices and margins are our estimates. Images are AI concept images.
   381→
   382→**Built with.** Next.js, TypeScript, Tailwind, Zod; Groq/Gemini/Cloudflare (free tiers) for the LLM; Cloudflare Workers AI (FLUX.1 schnell) for images; Qloo hackathon API; Vercel. Runs entirely on free tiers. MIT licensed.
   383→
   384→**What's next.** Fan Crate bundles, shareable collections, multi-currency, supplier quote requests.
