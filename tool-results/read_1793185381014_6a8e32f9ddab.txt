     1→     1→# MerchDesk — Technical Requirements Document
     2→     2→
     3→     3→## Assumptions
     4→     4→
     5→     5→- Next.js App Router, TypeScript strict, deployed to **Vercel Hobby** (free). Hobby is for non-commercial use: fine for a hackathon demo. If MerchDesk becomes a business, move to Vercel Pro or Cloudflare Pages.
     6→     6→- **No database, no auth.** State lives in React (`useReducer`) with a text-only copy in `sessionStorage`. Generated images stay in memory only (too big for sessionStorage).
     7→     7→- **No paid SDKs.** LLM, Qloo and image calls use plain `fetch`. This removes SDK version drift and keeps the dependency list tiny.
     8→     8→- **Qloo parameter names below are from public hackathon projects and developer notes, not from the official docs** (docs.qloo.com blocked automated reading). The adapter `lib/qloo/client.ts` is the only place that knows parameter names. Phase 2 of the plan verifies every call with a probe script before anything else is built.
     9→     9→- Free-tier limits change. Numbers below were checked in October 2026 from public sources and **must be re-checked in each provider's dashboard** on build day.
    10→    10→- Package versions are known-good majors. After first `npm install`, **commit `package-lock.json` and do not upgrade during the hackathon.**

    14→    14→## Free-tier compliance (the "free of cost" contract)
    15→    15→
    16→    16→| Need | Service | Free allowance (verify in dashboard) | If exhausted |
    17→    17→|---|---|---|---|
    18→    18→| Hosting + API routes | Vercel Hobby | Free forever, non-commercial; function max duration is 10 s default and configurable to 60 s (some sources list higher; we set `maxDuration = 60`, valid under either reading) | Site pauses until reset; no charge |
    19→    19→| Taste data | Qloo hackathon API | Key issued by organizers; works only on `https://hackathon.api.qloo.com`; keys expire after the event | Show "Qloo unavailable" + retry |
    20→    20→| LLM (primary) | Groq free tier, `llama-3.3-70b-versatile` | Rate-limited free tier, OpenAI-compatible, supports tool calling | Fall to next provider |
    21→    21→| LLM (fallback 1) | Google AI Studio, `gemini-2.5-flash-lite` | Free tier; **Flash-Lite is the safe free choice** — reports conflict on whether 2.5 Flash is still free, so the model name is an env var | Fall to next provider |
    22→    22→| LLM (fallback 2) + images | Cloudflare Workers AI (Free plan) | 10,000 neurons/day, no card. FLUX.1 [schnell] ≈ 43–58 neurons per 1024² image per Cloudflare-based sources (≈170–230 images/day); other write-ups quote higher per-image costs, so **budget for ≥50/day** | SVG sketch stays; text still works |
    23→    23→| Domain | `*.vercel.app` | Free | — |
    24→    24→| Repo | GitHub public | Free | — |
    25→    25→
    26→    26→**Hard rules**
    27→    27→1. Never add a payment method to Groq, Google AI Studio, Cloudflare, Vercel or Qloo. A free plan with no card cannot overspend.
    28→    28→2. Cloudflare account stays on the **Free** plan (not Workers Paid).
    29→    29→3. Gemini image models (Nano Banana / Imagen) have **no free API tier** — do not use them.
    30→    30→4. Any new service added later must pass: free tier exists, no card needed, works from a Vercel serverless function.
    31→    31→
    32→    32→**Per-run quota math (typical):** ~10–12 Qloo calls, ~6–8 LLM calls (agent loop 3–6, descriptions 1, classify 0–1, compare 0–1), 0 image calls until approval, then 1 per approved product (≤ 8 + regenerations).

   105→   105→
   106→   106→**Data flow in one run**
   107→   107→1. `POST /api/agent/profile` streams agent steps → client builds `TasteProfile`.
   108→   108→2. User confirms/edits chips → `POST /api/collection` → scored `ProductProposal[]` (descriptions via one batched LLM call, or template fallback) + `DropPlan`.
   109→   109→3. Per product: user approves → `POST /api/image` → `data:` URL shown. Reject → `POST /api/replace`.
   110→   110→4. `POST /api/collabs` fills Collab Radar. `POST /api/compare` runs lazily.
   111→   111→5. `/line-sheet` reads `sessionStorage` and prints.

   241→   241→## Third-party Integrations
   242→   242→
   243→   243→### 1. Qloo (hackathon API) — `lib/qloo/client.ts`
   244→   244→
   245→   245→- Base: `https://hackathon.api.qloo.com`. All calls are **GET** with header `X-Api-Key: <key>`.
   246→   246→- Entity type URNs to use: `urn:entity:artist`, `urn:entity:brand`, `urn:entity:place`, `urn:entity:movie`, `urn:entity:tv_show`, `urn:entity:book`, `urn:entity:podcast`, `urn:entity:videogame`, `urn:entity:destination`. **`urn:entity:video_game` returns HTTP 400 — use `videogame`.**
   247→   247→- Adapter methods (the rest of the app never builds a Qloo URL):
   248→   248→
   249→   249→| Method | Request (believed shape — verify in Phase 2) | Returns |
   250→   250→|---|---|---|
   251→   251→| `searchEntities(query, type, take=5)` | `GET /search?query=…&types=urn:entity:artist&take=5` | `QlooEntity[]` |
   252→   252→| `searchTags(query, take=5)` | `GET /v2/tags?filter.query=…&take=5` | `QlooTag[]` |
   253→   253→| `tasteTags({entityIds, tagIds, take=15})` | `GET /v2/insights?filter.type=urn:tag&signal.interests.entities=…&signal.interests.tags=…&take=15` | `QlooTag[]` with affinity scores |
   254→   254→| `related({type, entityIds, tagIds, location?, excludeEntityIds?, take=10})` | `GET /v2/insights?filter.type=<urn>&signal.interests.entities=…&signal.interests.tags=…&filter.location.query=<city>&filter.exclude.entities=…&take=10&feature.explainability=true` | `QlooEntity[]` with affinity and tags |
   255→   255→
   256→   256→- **Caching:** in-memory LRU Map keyed by full URL, TTL 30 min, max 200 entries. Reduces quota use and keeps demos fast.
   257→   257→- **Timeouts:** 8 s per call, 1 retry on network error or 5xx, no retry on 4xx.
   258→   258→- **Normalization (`normalize.ts`):** map each response to `QlooEntity { id, name, type, weight(0..1), tags: string[], imageUrl?, location? }`. If a numeric affinity score is absent, use rank-based weight `w = 1 − 0.7 × rank/N`. Drop entries without id or name. Unit-tested with synthetic JSON.
   259→   259→- **Errors:** `401/403` → `QLOO_NO_KEY`; `429` → `QLOO_RATE_LIMIT` (with `retryAfterSec` if header present); network/5xx → `QLOO_UNAVAILABLE`; `400` → logged with sanitized URL, surfaced as `QLOO_UNAVAILABLE` plus dev-only detail.
   260→   260→
   261→   261→### 2. LLM chain — `lib/llm/*`
   262→   262→
   263→   263→Providers share one OpenAI-compatible shape:
   264→   264→
   265→   265→| Provider | Endpoint | Auth | Tools |
   266→   266→|---|---|---|---|
   267→   267→| groq | `https://api.groq.com/openai/v1/chat/completions` | `Authorization: Bearer $GROQ_API_KEY` | yes |
   268→   268→| gemini | `https://generativelanguage.googleapis.com/v1beta/openai/chat/completions` | `Authorization: Bearer $GEMINI_API_KEY` | yes |
   269→   269→| cloudflare | `https://api.cloudflare.com/client/v4/accounts/$CF_ACCOUNT_ID/ai/v1/chat/completions` | `Authorization: Bearer $CF_API_TOKEN` | **no** (treated as text/JSON only) |
   270→   270→
   271→   271→```ts
   272→   272→// lib/llm/chat.ts
   273→   273→export interface ChatMessage { role: 'system'|'user'|'assistant'|'tool'; content: string; tool_call_id?: string; tool_calls?: ToolCall[] }
   274→   274→export interface ChatRequest { messages: ChatMessage[]; tools?: ToolSpec[]; json?: boolean; temperature?: number; maxTokens?: number }
   275→   275→export interface ChatResult { text: string; toolCalls: ToolCall[]; provider: ProviderName; model: string }
   276→   276→export async function chat(req: ChatRequest): Promise<ChatResult>  // tries providers in order
   277→   277→```
   278→   278→**Fallback rule:** on HTTP 429, 5xx, timeout (20 s) or unparseable response, try the next provider. If `tools` is set, skip providers without tool support. If no provider remains, throw `LLM_UNAVAILABLE` and callers use the **scripted** or **template** fallback.
   279→   279→
   280→   280→**JSON discipline:** every LLM JSON output is parsed with a Zod schema; on failure retry once with "Return only valid JSON matching the schema", then fall back.
   281→   281→
   282→   282→### 3. Cloudflare Workers AI image — `lib/image/cloudflare.ts`
   283→   283→
   284→   284→```ts
   285→   285→POST https://api.cloudflare.com/client/v4/accounts/${CF_ACCOUNT_ID}/ai/run/${CF_IMAGE_MODEL}
   286→   286→Headers: Authorization: Bearer ${CF_API_TOKEN}, Content-Type: application/json
   287→   287→Body: { "prompt": string, "steps": 6 }   // schnell: default 4, max 8
   288→   288→Response: { "result": { "image": "<base64 JPEG>" }, "success": true, "errors": [] }
   289→   289→```
   290→   290→- Server returns `data:image/jpeg;base64,<image>` to the client.
   291→   291→- Timeout 40 s. HTTP 429 or error code indicating daily limit → `IMAGE_QUOTA`. Other failures → `IMAGE_FAILED`.
   292→   292→- Width/height are assumed fixed (schnell default 1024²). Do not send them unless the docs for your chosen model list them.

   435→   435→## Agent Design — `lib/agent/*`
   436→   436→
   437→   437→**Principle:** the LLM *decides which Qloo calls to make*; it never *produces* data. Tool results are stored server-side in `AgentMemory`; the final `TasteProfile` is assembled from memory by code, not by the LLM.
   438→   438→
   439→   439→### Tools exposed to the LLM (`tools.ts`)
   440→   440→
   441→   441→| Tool | Args | Backed by | Result summary shown in UI |
   442→   442→|---|---|---|---|
   443→   443→| `qloo_search_entity` | `{query:string, type:'artist'\|'brand'\|'place'}` | `searchEntities` | "Found *X* (artist)" / "No match for *X*" |
   444→   444→| `qloo_search_tags` | `{query:string}` | `searchTags` | "Matched tags: a, b, c" |
   445→   445→| `qloo_taste_tags` | `{entityIds?:string[], tagIds?:string[]}` | `tasteTags` | "Audience taste tags: …" |
   446→   446→| `qloo_related` | `{type:'brand'\|'videogame'\|'tv_show'\|'movie'\|'book'\|'podcast', entityIds?, tagIds?}` | `related` | "12 related brands" |
   447→   447→| `note` | `{text:string}` | — | Free-text note shown in panel (max 160 chars) |
   448→   448→| `finish` | `{path:'A'\|'B', summary:string}` | — | Ends loop |
   449→   449→
   450→   450→**Guards:** max 8 tool calls; 45 s wall clock; arguments validated with Zod; entity/tag IDs in args must exist in `AgentMemory` (else the call is rejected with "unknown id" and the model is told); each tool result truncated to 12 items before being fed back to the model.
   451→   451→
   452→   452→### System prompt (`prompts.ts → AGENT_SYSTEM`)
   453→   453→
   454→   454→```
   455→   455→You are MerchDesk's taste researcher. Build an audience taste profile for a creator's fans using ONLY the provided Qloo tools.
   456→   456→
   457→   457→Rules:
   458→   458→1. If the user named an artist, call qloo_search_entity(type="artist") first. If no result clearly matches the name, do NOT guess. Call note("Not found in Qloo — trying genre and interest tags") and use qloo_search_tags with the genres/interests from the description and any "sounds like" names.
   459→   459→2. Call qloo_taste_tags once using the best seed ids you have.
   460→   460→3. Call qloo_related for type "brand" once. Then call it for up to 3 cross-domain types (videogame, tv_show, movie, book, podcast) that match what the fans are said to like. Skip types with no relevance.
   461→   461→4. Use only ids returned by tools. Never invent ids, names or facts about the artist.
   462→   462→5. Use at most 8 tool calls total. When you have taste tags, brands and at least one cross-domain list (or you have run out of useful calls), call finish.
   463→   463→6. Keep notes short and factual.
   464→   464→```
   465→   465→
   466→   466→### Scripted fallback (`scripted.ts`)
   467→   467→Used when no tool-capable LLM provider is available or the loop fails. Fixed sequence, no LLM: artist search if `input.artist`/text looks like a name; else split description into up to 4 keyword phrases and call `searchTags` for each → `tasteTags` → `related(brand)` → `related` for the first 2 cross-domain types detected by keyword (`game`→videogame, `show|series|tv`→tv_show, `movie|film`→movie, `book|read`→book, `podcast`→podcast). Marks `agentMode: 'scripted_fallback'`.
   468→   468→
   469→   469→### Classification step (`score/classify.ts`)
   470→   470→After tool results are in, entities with no mapping in `tag-aliases.json` / `brand-tiers.json` are classified in **one batched LLM call** into the fixed vocabularies (`canonical-tags.json`, brand categories) and flagged `estimated: true`. If the LLM is unavailable they are simply skipped (never guessed by code).

   474→   474→## Scoring, Selection, Pricing (deterministic; `lib/score/*`)
   475→   475→
   476→   476→### Mapping to canonical tags
   477→   477→`tag-map.ts`: lowercase → trim → exact match in `tag-aliases.json` → else substring match on alias keys → else unmapped (kept for display, not scored). Profile weight per canonical tag `P[c]` = max weight among tags mapping to `c`. Cross-domain weights `X[c]` built the same way from `crossDomain` and `inspirationPlaces` entities' `canonicalTags` × entity weight.
   478→   478→
   479→   479→### Fit score
   480→   480→```
   481→   481→tag    = clamp( Σ_{c ∈ item.tags ∩ P}            P[c] / 2 , 0, 1 )
   482→   482→brand  = clamp( Σ top2 over brands b with b.brandCategories ∩ item.brandCategories ≠ ∅
   483→   483→                    of (b.weight × (b.estimated ? 0.6 : 1)) / 2 , 0, 1 )
   484→   484→cross  = clamp( Σ_{c ∈ item.crossDomainTags ∩ X}  X[c] / 1.5 , 0, 1 )
   485→   485→fitScore = round( 100 × (0.5·tag + 0.3·brand + 0.2·cross) )
   486→   486→```
   487→   487→Evidence points per link = coefficient × (share of that term contributed by the link) × 100. Top 3 links by points are kept. Ties break on catalog `id` for determinism.
   488→   488→
   489→   489→### Selection (`rules.ts`)
   490→   490→Per-item first-run cap and total cap by budget:
   491→   491→
   492→   492→| Budget | Per-item first-run cap | Total first-run cap | Target size |
   493→   493→|---|---|---|---|
   494→   494→| small | $200 | $700 | 6 |
   495→   495→| medium | $600 | $2,200 | 7 |
   496→   496→| large | $1,500 | $6,000 | 8 |
   497→   497→
   498→   498→`firstRunCost = setupCost + minRun × mean(unitCost range)`.
   499→   499→1. Eligible = items with `firstRunCost ≤ perItemCap`.
   500→   500→2. Hero = highest-fit eligible item with `hero: true`; if none, highest-fit non-lowRisk eligible item.
   501→   501→3. Low-risk = highest-fit eligible item with `lowRisk: true`.
   502→   502→4. Fill by descending fit, skipping items that would make a category exceed 3 items or consumables exceed 2, stopping at target size or total cap.
   503→   503→5. If fewer than 3 categories, swap the lowest-fit item for the best-fit item from a missing category.
   504→   504→6. If fewer than 5 items fit, relax per-item cap by 25% once, then return what exists with a note.
   505→   505→7. Roles: hero → `hero`; the collab consumable or highest-priced non-hero item with `minRun ≤ 50` → `limited` (if any); rest → `core`.
   506→   506→
   507→   507→### Pricing (`pricing.ts`)
   508→   508→```
   509→   509→mult = { budget: 2.2, mid: 2.8, premium: 3.5 }[profile.priceTier]
   510→   510→unitCost = (lo + hi) / 2
   511→   511→price = charm( clamp(unitCost × mult, priceRange[0], priceRange[1]) )   // charm = nearest .00 or .50
   512→   512→marginPerUnit = price − unitCost
   513→   513→firstRunCost = setupCost + minRun × unitCost
   514→   514→breakEvenUnits = ceil(firstRunCost / price)  →  null if > minRun
   515→   515→```
   516→   516→`priceTier` comes from brands' tiers weighted by affinity (`brand-tiers.json`; unknown brands LLM-estimated, `priceTierEstimated=true`); default `mid`. Public benchmarks from the earlier research (stickers ≈ $5, posters ≤ $10, totes $15–25) are *guardrails already encoded in `priceRange`*; re-verify before quoting them publicly.
   517→   517→
   518→   518→### Drop plan (`drops.ts`)
   519→   519→| Wave | Week offset | Contents | Run size |
   520→   520→|---|---|---|---|
   521→   521→| core | 0 | all `core` products | `minRun` |
   522→   522→| hero | 2 | hero product, pre-order framing | `minRun` |
   523→   523→| limited | 5 | limited product, numbered edition | `minRun` |
   524→   524→Run size never exceeds `2 × minRun`. `firstRunTip` = "Order less than you think you'll sell — a sell-out creates demand." (from the earlier research; keep wording soft, no statistics).

   528→   528→## Image Pipeline (describe → approve → generate)
   529→   529→
   530→   530→```
   531→   531→catalog + profile ─► describeProducts() ─► ProductDescription (text only)
   532→   532→                                   │
   533→   533→              user edits/approves ─┘
   534→   534→                                   ▼
   535→   535→                 POST /api/image { approved: true, text }
   536→   536→                                   │
   537→   537→              moderation.check ─► sanitize ─► buildImagePrompt ─► Cloudflare FLUX ─► data URL
   538→   538→```
   539→   539→
   540→   540→1. **Description generation (`score/describe.ts` via `llm/prompts.ts → DESCRIBE_SYSTEM`):** one batched JSON call for all products. Input per product: catalog name/category/materials hints, top 3 canonical tags, palette color names. Output: `{id, name, oneLiner, visualDescription}`. Rules: 40–70 words; cover object, materials, colours (from palette), motif drawn from tags, overall mood; **no brand names, no artist name, no text or logo content**, no sales claims. Zod-validated; word count enforced (retry once, else template).
   541→   541→2. **Template fallback:** `"A {material} {noun} in {color1} and {color2}, decorated with a simple {motif} motif, finished in a {mood} style."` with motif/mood looked up from tag→phrase tables in `palettes.json`.
   542→   542→3. **Approval gate:** the client state machine (`studio-reducer.ts`) only dispatches `IMAGE_REQUESTED` from state `approved`. `/api/image` additionally requires `approved: true` and a non-empty `approvedDescription`; otherwise `422 VALIDATION`. A unit test asserts that no code path other than the approve action calls the image API.
   543→   543→4. **Moderation (`moderation.ts`):** remove (word-boundary, case-insensitive) the artist name, every Qloo-returned brand name in the profile, and a static list of major trademarks (e.g. Nike, Adidas, Supreme, Nintendo, Pokémon, Disney, Marvel, Carhartt) from the description. Reject with `MODERATION_BLOCKED` if it contains unsafe terms (weapons, nudity, slurs, real-person names list). Strip any "text saying", "logo", "slogan", "brand" phrases.
   544→   544→5. **Prompt template (`image/prompt.ts`):**
   545→   545→```
   546→   546→Studio product photograph of {categoryNoun}: {sanitizedDescription}. Colour palette: {paletteNames}. {palette.imageStyle}. Plain warm off-white seamless backdrop, soft natural shadow, centered {composition}, sharp focus, e-commerce catalog style. Blank unprinted label areas, no text, no letters, no logos, no watermark, no people.
   547→   547→```
   548→   548→`composition` by attempt: 1 = "front view", 2 = "three-quarter view", 3 = "flat lay from above". (FLUX has no negative prompt, so the constraints are phrased positively. Free text-to-image models often garble text even when told to avoid it; the UI labels outputs as concept images.)
   549→   549→6. **Session cap:** client refuses to call the API after `NEXT_PUBLIC_MAX_IMAGES_PER_SESSION` generations (counter in reducer).

   553→   553→## Error Handling Strategy
   554→   554→
   555→   555→| Layer | Condition | Handling |
   556→   556→|---|---|---|
   557→   557→| Route handler | Invalid body | `400` `{error:{code:'VALIDATION', field}}` via Zod |
   558→   558→| Route handler | Rate limit hit | `429` `RATE_LIMITED` + `Retry-After` |
   559→   559→| Qloo | No key / 401 / 403 | `503` `QLOO_NO_KEY`; UI: "MerchDesk can't reach its taste data right now" + retry |
   560→   560→| Qloo | 429 | `503` `QLOO_RATE_LIMIT`; UI shows retry-after |
   561→   561→| Qloo | 5xx/timeout | 1 retry then `503` `QLOO_UNAVAILABLE` |
   562→   562→| Agent | Tool arg invalid / unknown id | Return error text to model once; second failure aborts loop → scripted fallback |
   563→   563→| Agent | 45 s budget hit | Emit `note`, build profile from memory so far, continue |
   564→   564→| LLM | All providers fail | `LLM_UNAVAILABLE` → scripted agent, template descriptions, skip compare panel with message |
   565→   565→| Image | Daily quota | `429`-like → `IMAGE_QUOTA`; card keeps sketch |
   566→   566→| Image | Other failure | `IMAGE_FAILED`; card offers Retry (counts as an attempt only on success) |
   567→   567→| Client | Network error | Toast "Connection problem — try again", action buttons re-enabled |
   568→   568→| Client | Unhandled render error | `app/error.tsx` shows "Something went wrong" + Reload; state in sessionStorage is kept |
